# R6：完整约束块构造开发协议

登记日期：2026-11-11。此协议在本轮300件运行前写入；源实例已在R5反复使用，属于开发实例，不称盲测。

## 研究问题

在不改动R5的L4主情景、`chain_area_v1`、普通支撑比例0及3cm顶部余隙的条件下，整体构造标准底座与易碎顶层，是否比逐件EP更容易找到一大车或两小车的完整运输布局？P1最少车辆与P2最低成本仍分别评价。只有300件全量、身份守恒、独立核验零违规的方案可参与运输目标排名。

## 方法与适用范围

- 新增独立模块`src/block_search.py`，不覆盖R5 EP或作者程序。
- 将标准件按相同底面堆成柱，或两列拼成等高平台；部分平台顶层放一件易碎件；定向件按原姿态成柱。
- G1柱采用60×40底面、30高度，易碎帽采用50×40底面、70高度；G2成对35×50底面、25高度，平台70×50，易碎帽70×50×40。定向件G4/G5保持题面原姿态，整块不作水平旋转。
- 使用互不重叠的落地块，块内部顺序自下而上；整块旋转仅用于全部成员允许该姿态的标准/易碎块。
- 块柱高度及数量上限限制顶面平均外载；实际每件仍由`ChainTruck.put`检查，最终另用`src.constraints.check_fleet`检查。
- 地面候选为0及已放块右边/上边坐标的笛卡尔积，按固定次序首次适配。不是完整二维排样或完整三维搜索；未放入不证明原问题不可行。
- 这是自研受限构造启发式，不声称实现某篇论文算法或达到完整约束SOTA；不增加力矩平衡或物理认证声明。

## 固定配置预算

两车队：一辆车型2、两辆车型1；有/无易碎帽；块排序area/long/volume/height；地面坐标优先yx/xy；可旋转块姿态优先original/wide/long。

总计2×2×4×2×3＝96个确定性配置。所有配置都运行，不因首次成功提前停止。不追加随机试验、不根据中途结果改变本矩阵。允许不同配置产生相同布局，不能视为96次独立随机实验。预算按构造配置和实际候选检查次数记录，不冒充等CPU预算对比。

## 证据与验收

- 运行器在首个求解前生成`plan.json`；输出每次布局、未装身份、配置、CPU/墙钟、块落地信息、载荷链审核、完整manifest及SHA256。
- 保存源数据、求解器、运行器和验证器代码快照；保留原R5结果。
- 只读验证器重建96配置矩阵，拒绝缺跑/重复/错配置/错文件集，核查哈希、跨车货物守恒、车队范围、逐件全部约束及P1/P2独立排名。
- 若发现完整方案，只对题面固定实例和已约定的操作模型作结论；泛化、参数鲁棒性、物理稳定性和AI提效比例仍需另做实验。
- AI作用记录：提出平台整体构造假设、编写实现及测试、自动执行和读回；本轮无无AI对照，因此不量化AI节时百分比，也不将本轮算法收益等同AI流程效率收益。
