# 04 基线算法、外部校准与后续强基线

> 本文说明当前算法是什么、校准结果说明什么、为什么不能称为 SOTA，以及 MES + Beam 首版实现的真实表现与边界。
> 所有结论均区分文献报告、仓库实测和待验证假设。检索与复查日期：2026-11-10。

---

## 1. 当前基线：EP-FF

当前基线正式命名为：

```text
EP-FF = Extreme Point + First-Fit + 体积降序
```

它由以下组件构成：

| 组件 | 当前实现 | 性质 |
|---|---|---|
| 候选点 | 固定 7 个角点 | 工程简化 |
| 选择策略 | First-Fit，第一个可行位置即放置 | 单分支贪心 |
| 空间表示 | 三维整数占用栅格 | 离散碰撞检查 |
| 货物排序 | 体积降序为主 | 可切换高度/底面积等排序 |
| 容器策略 | 先试已有车辆，失败后开新车 | 多容器 First-Fit |
| 最终检查 | 独立校验器 `src/constraints.py` | 不调用求解器内部状态 |

重要声明：

- EP-FF 不是任何一篇论文的完整忠实复现；
- 它不是 SOTA；
- 它的价值是简单、透明、可复现，适合做 L0–L4 约束消融的共同起点；
- 其结果只能解释为“在该算法、该排序、该算例下的结果”。

### 1.1 伪代码

```text
输入：货物集合 I，车辆类型集合 K，顶部余隙 d
输出：车辆列表 T，未装货物 R

T ← []
R ← []
for item in sort(I, key = -volume):
    placed ← False
    for truck in T:
        for p in sort(candidate_points(truck), key = (z, y, x)):
            for orientation in allowed_orientations(item):
                if feasible(truck, item, p, orientation):
                    place(truck, item, p, orientation)
                    placed ← True
                    break
            if placed: break
        if placed: break
    if not placed:
        for orientation in allowed_orientations(item):
            if feasible(new_truck, item, origin, orientation):
                place(new_truck, item, origin, orientation)
                T.append(new_truck)
                placed ← True
                break
    if not placed:
        R.append(item)
return T, R
```

## 2. 为什么当前 EP-FF 不是 SOTA

结构对照提示，当前实现与候选强方法的重要差异在搜索结构；尚未通过完整消融证明它是全部性能差距的唯一原因：

| 维度 | EP-FF | 强基线方向 |
|---|---|---|
| 部分解数量 | 每一步只保留 1 个 | Beam 同时保留多个 |
| 剩余空间 | 角点集合 + 栅格 | maximal empty spaces |
| 回溯 | 无 | 有限回溯/树搜索 |
| 货物动作 | 逐件 | 逐件、块构造或组合动作 |
| 评价 | 当前可行即落子 | 预估完成质量后排序 |
| 多容器选择 | 装不下才开新车 | 外层车型组合与内层装载联动 |

因此，当前标准算例的 81.9% 与 Guesser 2026 EJOR 的 95.91% 之间的差距，不能简单归因于“代码写错”，也不能据此说当前算法接近 SOTA。更准确的表述是：

> 当前 EP-FF 是一个可运行的弱基线；下一步要更换搜索框架，而不只是继续增加廉价候选点。

## 3. 外部校准：OR-Library `thpack1`

### 3.1 数据和口径

| 项 | 取值 |
|---|---|
| 数据集 | OR-Library `thpack1` |
| 算例数 | 100 |
| 容器尺寸 | 587×233×220 cm |
| 容器数 | 1，硬性固定 |
| 姿态 | 按数据中的 0/1 方向标记 |
| 目标 | 装入体积 / 容器体积，即 ISD |
| 题面约束 | 仅标准算例支持的几何与姿态口径 |
| 时间 | 当前实现平均约 2.35 秒/算例 |

### 3.2 实测结果

- 平均 ISD：81.9%；
- 中位数：82.4%；
- 最高：92.1%；
- 最低：67.3%；
- 标准差：4.8 个百分点；
- 件数规模：69–476 件。

该数字支持“实现可运行且可作为弱基线”，不支持“已经达到 SOTA”。三算例复核不是这100例的替代重跑。

### 3.3 与论文报告值的正确比较

| 方法 | 问题 | 平均指标 | 时间 | 代码 |
|---|---|---:|---:|---|
| EP-FF（本仓库） | 单容器几何校准 | 81.9% | 约 2.35 s | 有 |
| Guesser et al. 2026 EJOR | 单容器几何 | 95.91% | 30 s | 有，GitHub/Zenodo |

这些数字不能直接横向排名，因为时间预算、候选空间、实现、实例子集和目标口径并不完全相同。正式报告应把 Guesser 95.91% 标作“文献报告的几何强基线”，而不是“本仓库已经复现的结果”。

## 4. 已完成机制对照

### 4.1 候选点加密

同一贪心框架下对比 `corner7`、`face3` 和 `topgrid`：

- `face3` 与 `corner7` 结果相同；
- `topgrid` 在已测 3 个算例中更慢且最差约 3.6 个百分点；
- 因此“候选点越多越好”不成立，候选点加密需要配合更强搜索。

### 4.2 随机贪心重启

在 `thpack1` 算例 1 上，20 轮随机排序取最优与单轮 EP-FF 没有增益：

```text
单轮：84.4%
随机重启 20 轮：84.4%
```

限定性结论是：在当前固定候选点和单分支贪心骨架下，简单 RGS 没有带来可见收益。这不能推出 RGS 在其他搜索框架中无效。

### 4.3 B2首版：MES + Beam 组件校准

B2首版保留严格的单容器、L0、轴对齐几何口径，使用极大空闲空间的有界表示与Beam保留多个部分布局；实现文件为 `src/mes_beam.py`，运行器为 `experiments/bench_mes_beam.py`。它没有加入易碎、支撑、承重、多车和块构造，因此不能称为完整论文复现或本题强基线。

在 `thpack1` 前3个算例、同一体积降序和单容器口径下：

| 方法 | Beam/空间参数 | 平均ISD | 备注 |
|---|---|---:|---|
| EP-FF | 单分支固定角点 | 85.9% | 3例复核 |
| B2 MES+Beam | width=8, space=80 | 77.3% | 首版组件 |
| B2 MES+Beam | width=1, space=80 | 74.6% | 统一重跑 |
| B2 MES+Beam | width=4, space=80 | 76.1% | 统一重跑 |
| B2 MES+Beam | width=8, space=80 | 77.3% | 统一重跑 |
| B2 MES+Beam | width=16, space=80 | 77.3% | 统一重跑 |

按不同排序，早期同口径探索中B2 width=8/space=120在高度降序为77.9%、底面积降序为77.3%；对应EP分别为83.4%和85.3%。这些排序结果属于探索归档，不与本次稳定w*/s80扫描混写。因此首版B2在当前实现、评分函数和三算例样本上**没有形成改进证据**，不能把“引入Beam”自动写成性能提升。更可能的待诊断因素包括：空间切分碎片化、当前评分函数只偏好已放体积、跳过动作导致状态竞争、候选空间截断以及尚未实现的论文级double-effort/块构造/记忆化。

这次负结果仍有研究价值：它说明“把EP的候选点替换成MES并加Beam”不是充分的强基线实现。小规模裁判采用单容器、轴对齐、正整数尺寸与整数坐标，枚举完整有限网格；其 `optimal` 仅对这个明确离散模型成立，不是一般连续坐标 MILP/CP-SAT，也不含支撑、易碎、承重或多容器约束。固定5件实例 `b2_gap_5` 在统一体积降序顺序后，B2与裁判均放5件、体积308；此前报告的B2放4件/248体积是旧运行器与B2排序不一致造成的，已撤回。固定3件实例 `b2_gap_3` 在统一排序下裁判为3件/27体积、B2为2件/15体积，给出当前有界B2在此布局动作规则下的可复现实例差距。评分优先级消融（volume优先 vs count优先）在这三个小实例以及 thpack 前3例未见结果差别；不据此推广为一般结论。正式结果见 `experiments/results/small_l0_referee_v1.json`、`mes_score_ablation_v1.json` 与校准JSON。

## 5. 约束层级结果

固定同一 EP-FF、排序和算例，依次加入约束：

本次两车型五层重新运行，十个配置全部复现表中车辆数，均未装0件、按层独立检查违规0条，记录于 `review_v04_regression.json`。L2同时加入C5/C6，不能只归因于C6。

| 层级 | 车型 2 车辆数 | 车型 2 成本 | 车型 1 车辆数 | 车型 1 成本 |
|---|---:|---:|---:|---:|
| L0 刚体 | 1 | 700 | 2 | 900 |
| L1 +支撑 | 1 | 700 | 2 | 900 |
| L2 +易碎 | 2 | 1400 | 3 | 1350 |
| L3 +定向/重心 | 2 | 1400 | 3 | 1350 |
| L4 +承重 | 2 | 1400 | 3 | 1350 |

正确结论：

> 在当前固定 EP-FF、排序和附件 1 算例下，L2 易碎件规则是车辆数的主要断点。

不能升级为全局结论：

- 易碎件约束对所有算法必然使车辆数增加；
- 车型 2 一辆车在完整约束下必然无解；
- 搜索顺序一定是唯一瓶颈。

## 6. 易碎件平台诊断：已修正的证据等级

早期平台分析统计出 7,602 个满足局部条件的候选位置，并将面积折算为约 39 件易碎件。复查发现这些位置大量重叠，位置数不能直接累加，面积折算也不是二维或三维排布证明。

本次发现旧候选函数只检查底面切片，已改为完整候选长方体净空、直接承压及非重叠检查，并真实重跑：

- 固定70×50×40姿态：7,602个重叠候选，确定性贪心选择7个；
- 六姿态：38,387个重叠候选，确定性贪心选择18个；
- 前两轮约21–23个来自其他候选/选择规则，不是本次输出；
- 选择数不是最大值或不可行证书；冻结宿主已有全部货物，候选并非300件迁移后的完整解。

因此当前应写成：

> L0 布局上的候选平台分析提示平台碎片化和搜索起点可能是重要瓶颈；但候选位置统计不能证明一辆车全约束可行，也不能证明全局无解。下一步必须做实际迁移、局部重排或系统搜索。

## 7. 推荐强基线路线

### B2：MES + Beam Search

参考 Guesser et al. 2026 EJOR，第一优先级实现：

该实现是组件级强基线计划，尚未运行，不等于完整复现原文（其块构造、double-effort、评价和记忆化仍需对应）。

1. 用极大空闲长方体记录剩余空间；
2. 每个状态保留多个可行部分布局；
3. 每层生成若干候选放置动作；
4. 用启发式评分保留 beam width 个状态；
5. 最终用同一个独立校验器验收。

当前代码的 `state_priority` 支持 `volume`（原默认）与 `count`（件数优先消融）；当前L0小样本和thpack前三例未显示切换带来差别。它只是首版候选策略，不是论文级评价函数。

推荐先做：

```text
L0 + 单容器 + thpack 标准算例
```

再做：

```text
L0/L1/L2 + 车型 1/车型 2 + 附件 1
```

这样可以明确区分“几何搜索提升”和“易碎件约束提升”。

### B3：Block-building + MES + Beam

本题货物类型少、重复件多，适合：

- 同类货物先构造规则块；
- 相近尺寸货物构造组合块；
- 将块放入 MES；
- 用 Beam 保留不同平台结构。

重点指标不是只看体积率，还要看：

- 可形成的连续标准件顶面面积；
- 可放置的易碎件数；
- 未装货物数；
- 车辆成本。

### B4：混合车型外层优化

外层枚举有限车型组合 `(n_1,n_2)`，内层调用 B0/B2/B3，统一输出：

```text
车辆数、总成本、未装件数、装载率、独立校验结果、耗时
```

当前只跑单车型，不能声称已经解决成本最优的混合车队问题。

### 精确验证器

在 8–20 件缩小实例上使用 CP-SAT/MILP/分支搜索：

- 验证车辆数下界；
- 验证易碎件可行性；
- 验证定向件重心；
- 计算启发式 gap；
- 作为算法比较的裁判。

## 8. 公平比较协议

所有算法必须统一：

1. 输入货物和车型；
2. 顶部余隙；
3. 姿态允许集合；
4. L0–L4 约束层；
5. 时间预算或状态预算；
6. 随机种子；
7. 独立校验器；
8. 指标定义。

主指标：

- 是否全部装完；
- 车辆数；
- 总成本；
- 相对算术下界的增量；
- 未装件数；
- 独立校验违规数。

辅助指标：

- 装载体积率；
- 易碎件装入数；
- 连续平台面积和碎片数；
- 求解时间；
- 随机算法均值、最好值和标准差。

算法内部的 `feasible()` 不能代替最终独立检查。

## 10. 局限

1. EP-FF 是弱基线，B2仅实现MES+Beam组件，B3尚未实现；
2. 尚未在同一机器、同一批实例上运行 Guesser 官方代码；
3. L0–L4 主要是固定算法下的消融，不是全局最优性证明；
4. 易碎件平台的 39 件折算已撤销，完整一车可行性尚未解决；
5. 参数区间扫描尚未完成；
6. 小规模裁判已完成单容器整数网格L0版本；L1–L4、多容器与一般连续坐标精确模型尚未完成；
7. B1 承重模型未沿完整堆叠链传递载荷；
8. `topgrid` 和 RGS 的负面结果样本较小，只能作为当前实现的观察。
