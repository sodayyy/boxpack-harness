# 00　赛事要求（原文摘录与对齐）

> 依据：`00a-官方通知原文.txt`（赛道二部分位于 L126–L174）。
> 本文只摘录与交付直接相关的条款，不改动原文措辞。

## 1. 赛题定位（L131）

> 要求学生以真实的学科问题为对象，借助大模型、科研知识库、科研智能体、Skills 与 MCP 等工具，完整走通一次科研流程，并产出可复现的数据与结论。

## 2. 六环节（L142，硬性）

必须覆盖：

1. 问题定义与文献调研
2. 研究设计与假设
3. 数据与模型构建
4. 计算或实验执行
5. 结果分析与验证
6. 结论与反思

## 3. 技术要求（L143–L148）

| 条款 | 原文 |
|---|---|
| 数据要求 | 必须要有相关的实验数据和计算结果分析，**不接受纯文献综述、纯观点论述或无数据支撑的方案设想** |
| 实验形式 | 不要求湿实验，可以仅采用干实验方式（数据分析、建模、仿真计算等） |
| 模型要求 | **必须使用**了大模型或领域科研模型（大模型或小模型） |
| 工具要求 | **必须使用**了科研知识库、科研智能体（含 Harness）、Skills、MCP 中的一项或多项 |
| 软件许可 | 允许使用各类科研软件和工具（MindScience、PaddleScience、LAMMPS、OpenFOAM 等） |

## 4. 操作环境（L150–L154）

大模型/领域模型：不限，云端或本地自建均可。
科研工具：不限，建议优先开源或国产。
算力环境：不限，个人计算机即可。
数据合规：涉及个人信息或敏感数据须符合伦理与数据安全规定。

## 5. 作品提交

### 初赛（L156–L167）

| 材料 | 规格 |
|---|---|
| 方案书 | PDF，**不少于 5000 字** |
| 方案讲解 PPT | **正文 10–15 页** |
| 演示视频 | **3–5 分钟**，须完整展示研究流程、关键操作过程与结果 |

**方案书 8 节（顺序不可合并）**：

1. 研究问题陈述与选题依据
2. 文献综述
3. 研究设计与技术路线
4. 数据来源与处理说明
5. 计算或实验执行过程说明
6. 结果分析与验证
7. 研究结论与局限性说明
8. **人工智能使用说明**（各环节 AI 模型和工具的实际作用、贡献与局限）

### 决赛（L169–L174）

在初赛作品基础上，于 PPT、文档、视频中各补充 5 项：研究价值、科研模型、科研智能体、结果验证、落地应用。

## 6. 评分导向（L139，最关键）

> 本赛题重点考察参赛选手使用 AI 辅助全流程科研的能力**以及取得的研究成果**；**不评价**所采用或开发的人工智能技术和工具本身的复杂度和先进性。

这句话决定了两个取舍：

- **不靠技术炫技得分** → Lean 形式化定位为加分项，不得挤占六环节完整性
- **必须有「研究成果」** → 只报「2 辆装完」不够，必须有一句自己下的判断

## 7. 题目自带的额外要求

题面 PDF 问题 3 的说明 1：

> 请各个参赛队务必上传**算法执行的程序附件**，组委会评阅时会**运行测试程序**打分。

这使「程序能否跑起来」本身成为评分项，因此本仓库包含：

- `requirements.txt`（依赖声明）
- `data/*.csv`（数据可复现）
- README 第 7 节的运行命令
- `experiments/test_constraints.py`（可自证的测试）

## 8. 本项目与要求的对应

| 官方要求 | 对应物 |
|---|---|
| 六环节 | README 第 1–4 节 + `01-问题与约束.md` + `PROGRESS.md` 台账 |
| 有实验数据与分析 | 全部数字来自实跑；校验器 0 违规 |
| 大模型 / 领域模型 | 领域模型 = 装箱求解器；大模型用于文献表、代码生成、误差归因 |
| 科研知识库/智能体/Skills/MCP | 自建 harness（README 第 4 节 L1–L7）+ 会话工具链 |
| 方案书 8 节 | N4 交付至 `docs/report/` |
| 可执行程序 | 本仓库 |
| 可复现 | 固定 seed、CSV 数据、独立校验器、Lean 定理 |
