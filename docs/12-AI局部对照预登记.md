# AI局部对照预登记 v1

登记日期：2026-11-11。状态：**仅登记，尚未分配受试者、未计时、未执行比较**。本协议不追溯性地给R1–R7虚构无AI基线，也不从运输成本降幅推断AI效率。

## 1. 要估计的量

在固定的装箱布局核验任务上，AI辅助是否减少“达到同一验收标准所需的人类实际投入”，并且不增加漏检？估计对象是局部任务和指定参与者/工具条件，不是全部科研流程，不推广为一般科研生产率。

## 2. 任务包及信息隔离

- 后续生成12个未向参与者展示的任务包，按输入规模与缺陷类型组成6个配对；每包包含目录、约束定义、完整候选布局和固定验收输出格式。
- 4包合法、8包各含一个预设缺陷；缺陷覆盖身份/姿态、重叠/边界、支撑类型、载荷链等。合法/缺陷比例仅对组织者可见。
- 任务输入、配对和答案在首次分配前冻结哈希；答案文件与评分脚本不提供给参与者或AI会话。
- R6/R7已公开布局只能用于练习，不作为未见评价集；不能声称参加本项目的助手对当前文件是盲测。
- 全部任务包完成后统一评分，过程中不根据结果换题、补样本或改主指标。

## 3. 比较条件

- A：人工＋项目文档＋编辑器/本地Python等非生成式工具，不使用生成式AI。
- B：人工＋相同基础工具＋生成式AI；记录模型/版本、实际提示与响应、会话次数及AI生成代码的运行和修改。
- 至少2名真实参与者，每个参与者仅做每对中的一包；跨参与者交换A/B，使同一人不重复看到同一实例。分配在开测前固定随机种子并保存，控制顺序效应。
- 未招募到真实人工条件时，只报告AI单条件任务记录，不伪造A组，不由AI角色扮演人工对照，不给比较节时率。

## 4. 事先固定的验收与预算

每包输出：可行/不可行判断、定位到货物身份及约束的依据、适用模型范围；合法包须逐项确认，错误包须定位真实缺陷而非只报泛化异常。统一独立裁判和人工核对评分，修复布局不是本任务必要目标。

单包最多30分钟实际人类操作，计算等待另记。时间到未达到验收标记为未完成/右删失，不以30分钟冒充真实完成时间。技术故障单独记录；未见结果前只能因输入确实损坏修补任务，保留原版本及理由。

## 5. 指标、分析与诚实边界

- 主指标：达到完整验收的人类活跃时间（含阅读、提示、审查、改错、复核）。未完成比例同时报告，不只筛选成功任务算“更快”。
- 质量门槛：可行性判断、真实缺陷定位、无虚构约束/结论；分别报告漏检、误报与质量不达标次数。
- 次指标：总墙钟、计算等待、建议被采纳比例、纠错次数、复核时间占比、AI调用及费用（若实际可获得）。
- 优先给逐包记录、配对差值、完成比例和中位数；样本小，只作描述性探索，不声称统计显著的普遍提效。
- 仅在两个条件实际执行且可比时给效率比；不能将失败样本删除后只报成功者节时率。报告参与者经验、工具差异、学习/顺序、同一AI编题评题等潜在偏差。

## 6. 与本项目现状的关系

R1–R7的AI辅助实现和自查日志可作为流程案例，但不是上述对照已执行的证据。本协议生成任务包、招募/安排真实参与者、计时与评分均尚未开展；开始执行前需向参与者明确记录范围并征得其同意。当前可以继续自动完成代码/证据基础设施，不冒充完成了人工实验。
