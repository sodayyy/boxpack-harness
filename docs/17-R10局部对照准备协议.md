# R10：局部核验对照材料准备协议

日期：2026-11-11。承接docs12预登记；本阶段只生成任务和组织者设施，不执行真实参与者实验，不报告AI效率。

## 1. 存储与信息隔离

- 任务输入、配对映射、预设答案、生成器与评分程序只保存于正式仓库外的本地组织者目录，不提交GitHub或完整公开Git备份。
- 公开仓库仅记录本协议、状态和限制，不保存能够恢复题目或答案的生成代码、种子或任务明文。完整本地组织者备份另行保存并校验SHA256。
- 文件夹分开不是访问控制或加密；组织者必须只向参与者/AI会话提供实际分配的单任务包，不能把答案、生成器或组织者压缩包交给参与者。
- 编题助手已知全部输入与答案，其自查不是盲测；参与者AI条件必须使用无组织者上下文的新会话。
- docs12已可能公开披露任务合法/缺陷比例，不能再保证该比例对浏览过项目资料的人保密。正式开测前登记资料接触史；若已接触任务/答案，则这些题不可作为该人的未见评价集，须另行版本化重编。

## 2. 冻结任务设计

共12个微型合成核验任务、6个配对，每任务12件货物；全部用新坐标与完整候选布局，不复用R6/R7公开布局作为未见题。只继承当前操作规则，不是MathorCup官方新数据，也不代表原300件难度。

4个合法任务组成2对；8个带单个预设缺陷任务组成4对。预设类别覆盖身份/姿态、重叠/边界、易碎支撑类型、竖向链载荷。单个预设缺陷指一个植入机制，并不承诺裁判只输出一行。每个任务须由裁判实际重查；合法任务另经整数几何/有理数阈值自查。

成对任务只按件数、场景结构与核验类别近似匹配；身份与姿态、重叠与边界配对内部并非同一难度，不能假称等难。分析应逐包报告，并登记任务类型/参与者/顺序等潜在混杂，不从小样本宣称普遍显著提效。

## 3. 分配与同意

生成两名参与者的匿名“待绑定槽位”排程，每槽位做6题，每对只看一题，每槽位A/B各3题；两槽位在每对中采用相反条件。种子与映射只放组织者包。

匿名槽位不是已招募参与者。排程是未绑定模板，不代表已分配真实人员；需至少两名真实参与者知情同意后才绑定槽位并锁定顺序。未经同意不录屏、不采集聊天或个人资料。经验、工具、模型版本和资料接触史需开测前登记。不记录密码或不必要身份信息。

A为人工+非生成式工具，B为人工+相同工具+生成式AI。两条件获得相同规则说明与输入；不给任何一方组织者答案或裁判实现。可以自行编写检查程序，须计入活跃时间。

## 4. 输出、计时与评分

任务输出固定JSON：可行性判断、违规规则/货物身份及定量依据、规则逐项确认、模型范围说明。单任务30分钟人类活跃时间预算。阅读、提示、审查、改错、复核均计入；计算等待与暂停另记。不足质量门槛不能因快速提交算完成。

自动评分程序只做结构/判断/规则与身份定位初筛；自由文本定量依据、虚构结论和逐项确认的语义必须由真实组织者人工复核。自动初筛通过不等于最终验收。组织者复核前状态固定为待人工审查，不虚构评分者。

时间表与日志模板初始为空，无伪造完成时间、参与者或响应。最终应记录活跃时间、墙钟、等待、复核时间及AI调用信息，主指标只能在达到同一完整验收后计算。超时未通过标未完成/右删失，不能把预算当真实完成时间。技术故障另记。

## 5. 准备验收

实际生成并核验12输入/目录/候选布局、配对与4合法8缺陷类别；测试合法全部接受、预设缺陷触发、重哈希后语义篡改仍拒绝、评分初筛不冒充最终验收、任务包无答案泄漏字段。保存源码快照、manifest和SHA256；完整本地备份必须实际解压到新目录复核。

正式开测及结果分析仍待真实参与者、同意、槽位绑定和计时。当前产出只能称“准备材料可用”，不能称AI节时或漏检率已验证。
