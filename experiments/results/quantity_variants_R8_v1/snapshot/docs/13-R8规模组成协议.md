# R8：规模与货物数量组成的开发实验协议

登记日期：2026-11-11。沿用R6块构造、当前L4操作模型（chain_area_v1，α=0，p=500kg/m²，δ=3cm）；不修改原始CSV或R6/R7结果。以下矩阵在首个派生实例求解前冻结。

## 1. 目的与限制

研究同一受限块构造在规模和货物数量组成变化时能提供哪些完整运输见证，哪些场景暴露搜索缺口。不是官方新算例、盲测、SOTA比较或原问题的完整可行域枚举。

只调整数量，不改原五类尺寸、属性、重量和姿态。易碎数量、定向数量变化会同时改变总件数、体积与重量；因此称“数量组成扫描”，**不是固定体积/重量下某约束或某比例的因果效应**。报告实际件数比例，不把数量因子当比例本身。

## 2. 固定派生目录

基准数量向量为(G1,G2,G3,G4,G5)=(80,100,30,40,50)。基准只运行一次，供三条扫描共享：

- base：原始数量。
- scale_1_2、scale_3_2、scale_2：全部数量乘1/2、3/2、2；与基准组成规模轴150、300、450、600件，全部精确整数，不四舍五入。
- fragile_0、fragile_15、fragile_45、fragile_60：只把G3改为0、15、45、60；与基准G3=30组成易碎数量轴，其余四类不变。
- oriented_0、oriented_1_2、oriented_3_2、oriented_2：仅G4/G5同时乘0、1/2、3/2、2；与基准组成定向数量轴，其余三类不变。

共12个不同目录。含0数量类别仍保留目录，不新增货物。每个目录展开独立serial=类别-三位序号；没有跨场景运输的身份合并。

## 3. 固定构造矩阵与预算

每实例固定6个同型车队：1/2/3/4辆小车、1/2辆大车；每车队4个排序area/long/volume/height，统一有易碎帽、yx坐标序、original姿态序。共12×6×4=288个确定性构造配置，成功不提前停止，失败不临时追加预算。

R6算法要求同车高车队，本轮不为支持混合车队改写算法；**混合车队不搜索，但必须纳入全局目标下界的容量松弛**。不能把同型候选最优当全车型最优。每次记录实际非空车辆，不为未使用车辆收费。固定候选检查和构造次数不是等CPU性能对比；同源配置不当独立随机重复。

如果某车队被容量下界直接排除，本轮仍按协议运行其部分构造以保存算法表现，不把失败次数当不可行证明。严重代码/独立裁判错误应停机、保留输出、修复并在新目录重跑，不能过滤裁判错误。

## 4. P1/P2分别评价及证据类型

- 只用全量身份守恒、零违规的完整见证计算P1最少车辆与P2最低成本，两个目标分别选优；次级排序只用于等主目标的确定性见证选择，不限制P2的可行域。
- 每个实例针对全车型、允许混合的容量/载重松弛枚举：P1取可满足总有效容积及总载重的最少车辆数，P2取最便宜费用。对任意真实运输，它们都是有效下界，但不承诺几何可实现。
- 独立报告P1上下界是否相等、P2上下界是否相等。一个达到下界不替另一个宣称最优。
- 无完整见证时上界为null、状态未定；部分装载最多报告已装体积/件数，不称完成运输。
- 不从启发式失败推出原问题无解，也不把某类数量变化造成的结果差异全部归因于一种约束。

## 5. 保存与验收

首个构造前写plan.json及目录JSON/CSV，保存算法、运行器、验证器、原始CSV和本协议快照，保留288次逐件布局、未装serial、配置、搜索统计、CPU/墙钟和裁判结果。保存每实例摘要、逐运行CSV、全部哈希。输出路径已存在即拒绝覆盖。

只读验证器应从原目录与协议重建12实例、288配置；核查完整矩阵、目录、身份、姿态、几何、链载荷和指标、P1/P2分别排名及松弛下界、CSV/JSON一致、文件集与SHA256。完整方案再用R7整数几何/Fraction方法精确检查，独立于构造器；该方法及原裁判仍属项目自查，不称第三方审查。

如新增技术补丁，不改写实际运行快照。测试包含目录生成、数量守恒、零数量类别、两个目标独立、混合车型容量下界、证据缺跑/错目录。最终备份须实际克隆验证。
