# R9：R8费用缺口的混合车队开发协议

登记日期：2026-11-11。在第一次R9求解前冻结。沿用原五类尺寸/单重/属性与当前L4操作模型（chain_area_v1，α=0，p=500kg/m²，顶部余隙3cm）；不改R6/R7/R8证据或原`pack_blocks`接口。

## 1. 问题与构造方法

R8已有12目录完整见证，其中6目录费用未闭合。450/600件与定向180件的费用容量下界为1150元，来自一小一大；易碎45/60件及定向135件下界仍为700元。本轮问：新增混合车队见证能否降低各自费用上界？不能预先断言1150元或其他费用一定可行。

旧整体块构造只支持等车高。新增顺序重构策略：按声明车序依次对**当前剩余货物**调用旧单车`pack_blocks`，用本车有效高度生成块，装不下的货物在下一辆车重新组块。每辆已装车保持不动，不跨车支撑；这是一种受限异高启发式，不是对完整可行域的精确搜索，也不是同时联合分配最优。

一小一大车高不同，不能假称只改变车队类型就得到单因素因果比较。本轮同时新增车序与剩余货物重组策略；相对R8的改善只归因于新增构造路线提供了新见证，不量化单一组件效果。

## 2. 固定目录与预算

只取R8费用未闭合的6个目录，数量向量(G1,G2,G3,G4,G5)为：

| ID | 数量向量 |
|---|---|
| scale_3_2 | 120,150,45,60,75 |
| scale_2 | 160,200,60,80,100 |
| fragile_45 | 80,100,45,40,50 |
| fragile_60 | 80,100,60,40,50 |
| oriented_3_2 | 80,100,30,60,75 |
| oriented_2 | 80,100,30,80,100 |

每目录固定：

- 车队：恰好声明一小一大，车序小→大、大→小共2种；未使用车不计费。
- 排序：area、long、volume、height共4种，两阶段使用同一排序。
- 坐标优先：xy、yx共2种。
- 块姿态序：original、wide、long共3种。
- 有易碎帽`capped=True`固定。

共6×2×4×2×3=288项确定性构造。成功不提前停止，失败不临时追加；不搜索三车混合、数量分配全枚举或随机种子。本轮开发集直接取自已知R8缺口，不是盲测、泛化评价或等CPU对比。

## 3. 分别评价P1/P2

运行前只读核验完整R8证据。各目录保留R8已有P1/P2见证，再与R9全部完整零违规记录合并，分别按车辆数、费用选优。次级排序仅确定等主目标时的见证，不限制另一目标的可行域。

容量/载重下界仍允许两车型全部组合，沿用R8有效下界并由当前目录独立重算。不因只搜索混合车队而将下界抬高。达到下界才证明对应目标最优；否则给区间。部分装载不提供完整运输上界，失败不等于原问题无解。

## 4. 保存与验收

首个求解前写`plan.json`、6目录与源码/CSV/本协议快照。保存288次完整/部分布局、剩余身份、每阶段输入/输出身份、原构造统计、求解CPU/墙钟与裁判结果、manifest、CSV/JSON摘要、环境亲和性和全部SHA256。已有输出目录拒绝覆盖，重大裁判错误保留证据并停机。

只读验证器不导入求解器或运行器；独立重建288配置与数量目录，核查阶段身份分割、车序、无额外车、原裁判逐件几何/支撑/载荷，完整方案再调用R7精确有理数方法。重算两个目标的合并选优与有效下界，核对CSV/JSON、文件集与哈希。共享裁判及精确方法仍属项目自查，不声称第三方审查。

新增测试覆盖身份守恒、可重复且不修改输入、车序固定、非法配置、目标分别选优，以及重哈希后缺跑/错目录/伪造指标等必须拒绝。全套测试通过后提交独立标签并建立完整历史备份，实际新克隆复核。
